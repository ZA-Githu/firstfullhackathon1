## ایک فرسٹ کلاس ہنر کے طور پر Prompt انجینئرنگ

ہر مؤثر prompt میں پانچ اجزاء ہوتے ہیں: **کردار، سیاق و سباق، ٹاسک، فارمیٹ، اور پابندیاں**۔

- **کردار** — AI کو بتاتا ہے کہ اس سیاق و سباق میں یہ کون ہے
- **سیاق و سباق** — پس منظر دیتا ہے جس کی اسے ٹاسک کو سمجھنے کے لیے ضرورت ہے
- **ٹاسک** — واضح طور پر بیان کرتا ہے کہ کیا کرنا ہے
- **فارمیٹ** — آؤٹ پٹ کی ساخت کو مخصوص کرتا ہے
- **پابندیاں** — فہرست بناتی ہے کہ کیا نہیں ہونا چاہیے

### Chain-of-Thought Prompting

AI سے نتیجہ اخذ کرنے سے پہلے قدم بہ قدم سوچنے کو کہیں۔ مثال کے طور پر:

```
کوئی طریقہ کار تجویز کرنے سے پہلے، تجارت کے ساتھ تین اختیارات کی فہرست بنائیں،
پھر وہ منتخب کریں جو ہماری پابندیوں پر سب سے بہتر فٹ بیٹھتا ہے۔
```

یہ لاگو ہونے والے فیصلوں سے پہلے خراب فرضیات کو سامنے لاتا ہے۔

### مستقل مزاجی کے لیے Few-Shot Prompting

جب ایک جیسے کئی آرٹیفیکٹس تیار کر رہے ہوں، ایک مکمل مثال فراہم کریں اور AI سے اس سے بالکل مماثلت کرنے کو کہیں۔ مثال کے بغیر ہر آؤٹ پٹ مختلف ہوتا ہے۔ اس کے ساتھ، آؤٹ پٹ مستقل اور قابل پیش گوئی ہوتا ہے۔

```
لاگ ان فیچر کے لیے یہ ایک مثال spec ہے:
[مثال SPEC]

اب پاس ورڈ ری سیٹ فیچر کے لیے بالکل اسی فارمیٹ میں spec تیار کریں۔
```

### عام ناکامی کی موڈز

| ناکامی کی موڈ | نتیجہ | ٹھیک کریں |
|---|---|---|
| دھندلا اسکوپ | غلط عمل درآمد | سرحدوں کے بارے میں واضح رہیں |
| غائب فارمیٹ spec | غلط آؤٹ پٹ شکل | ایک مثال آؤٹ پٹ دکھائیں |
| غائب پابندیاں | غلط ٹیکنالوجی انتخاب | استعمال نہ کرنے کی فہرست بنائیں |
| ٹاسک بہت بڑا ہے | بغیر جائزہ کے نتائج | spec-plan-tasks-implement میں تقسیم کریں |

### Prompt لائبریری بنانا

اعلیٰ کارکردگی والے prompts کی ایک ورژن شدہ لائبریری برقرار رکھیں جو احاطہ کرتی ہے:
- Spec جنریشن
- آرکیٹیکچر جائزہ
- کوڈ جائزہ
- ڈی بگنگ سیشنز
- دستاویزات

اسے ایک حریف اثاثہ کے طور پر سلوک کریں جو وقت کے ساتھ قدر کو مرکب کرتا ہے۔ اسے کوڈ کی طرح ورژن کریں۔ جب بھی آپ ماڈلز کو اپ گریڈ کریں تو لائبریری کا ٹیسٹ کریں۔

:::tip
اپنی prompt لائبریری کو ٹیم میں شیئر کریں۔ ایک بار لکھا گیا ایک عظیم prompt سب کو فائدہ پہنچاتا ہے۔ سب کے ذریعہ استعمال کیا گیا ایک برا prompt سب کو نقصان پہنچاتا ہے۔
:::
