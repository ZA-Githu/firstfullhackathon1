## Prompt انجینئرنگ بطور اولین درجے کی مہارت

ہر موثر prompt کے پانچ اجزاء ہوتے ہیں: **کردار، سیاق و سباق، کام، شکل، اور پابندیاں**۔

- **کردار (Role)** — AI کو بتاتا ہے کہ وہ اس سیاق و سباق میں کون ہے
- **سیاق و سباق (Context)** — وہ پس منظر دیتا ہے جو اسے کام سمجھنے کے لیے چاہیے
- **کام (Task)** — بالکل وضاحت کرتا ہے کہ کیا کرنا ہے
- **شکل (Format)** — آؤٹ پٹ کی ساخت بیان کرتی ہے
- **پابندیاں (Constraints)** — وہ فہرست جو نہیں ہونا چاہیے

### Chain-of-Thought Prompting

نتیجہ اخذ کرنے سے پہلے AI کو مرحلہ بہ مرحلہ استدلال کرنے کو کہیں۔ مثال کے طور پر:

```
Before recommending an approach, list three options with tradeoffs,
then choose the one that best fits our constraints.
```

یہ غلط مفروضوں کو سطح پر لے آتا ہے اس سے پہلے کہ وہ نافذ فیصلے بن جائیں۔

### مستقل مزاجی کے لیے Few-Shot Prompting

جب ایک سے زیادہ ملتے جلتے آرٹیفیکٹ تیار کر رہے ہوں، تو ایک مکمل مثال فراہم کریں اور AI کو اس سے بالکل ملانے کو کہیں۔ مثال کے بغیر ہر آؤٹ پٹ مختلف ہوتا ہے۔ اس کے ساتھ، آؤٹ پٹ مستقل اور قابل پیش گوئی ہوتا ہے۔

```
Here is an example spec for a login feature:
[EXAMPLE SPEC]

Now generate a spec in the exact same format for a password reset feature.
```

### عام ناکامی کے طریقے

| ناکامی کا طریقہ | نتیجہ | حل |
|---|---|---|
| مبہم دائرہ | غلط نفاذ | حدود کے بارے میں واضح رہیں |
| غائب شکل کی وضاحت | غلط آؤٹ پٹ شکل | ایک مثال آؤٹ پٹ دکھائیں |
| غائب پابندیاں | غلط ٹیکنالوجی انتخاب | کیا استعمال نہ کریں کی فہرست بنائیں |
| کام بہت بڑا | بلا جائزہ نتائج | spec-plan-tasks-implement میں توڑیں |

### Prompt لائبریری بنانا

اعلی کارکردگی والے prompts کی ورژن شدہ لائبریری برقرار رکھیں جس میں شامل ہوں:
- Spec تیاری
- آرکیٹیکچر جائزہ
- کوڈ جائزہ
- Debugging سیشن
- دستاویز سازی

اسے ایک مسابقتی اثاثہ سمجھیں جو وقت کے ساتھ قدر مرکب کرتا ہے۔ کوڈ کی طرح ورژن کریں۔ ماڈل اپ گریڈ کرتے وقت لائبریری کی جانچ کریں۔

:::tip
اپنی prompt لائبریری پوری ٹیم میں شیئر کریں۔ ایک بار لکھا گیا اچھا prompt سب کو فائدہ دیتا ہے۔ سب کی طرف سے استعمال ہونے والا خراب prompt سب کو نقصان دیتا ہے۔
:::
